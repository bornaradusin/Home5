### Test version 3 — for trying on hardware

A **pre-release** for testing (the updater and ProsperoStore leave it alone). Download `PPSA11019-test.zip` and `PPSA11019-reader.elf` by hand. Reports on the [Shortcuts issue](https://github.com/bornaradusin/Home5/issues/3).

### Since test 2

- **Rumble strength and length are yours to set.** On the Shortcuts screen, two rows under the master switch — press left/right to adjust. They apply to the Rumble and All confirmations, and the reader picks them up.
- **The light-bar flash is being chased.** It fired in test 2 but the bar never changed. The reader now logs what `scePadSetLightBar` returns from inside `SceShellUI`, so the next `reader.log` should say whether the call fails or the game overrides the colour.
- **"Automations" is its own filter** in the action picker, next to "Scenes" — no longer only under "All", where automations with no area sat at the bottom.
- **Shortcuts can save mid-game.** The app now writes the reader config straight to `/system_tmp` (where the thread reads it) as well as `/data`, so a change made while a game has `/data` unmounted reaches the reader without restarting Home5 — if the app can write `/system_tmp` from its sandbox, which this build is the test of.

### Working in test 2

The shortcut, the Home Assistant call, the notification and the rumble all fire end to end while a game is in front. The light bar is the one piece left to confirm.

### Set-up order matters

Set your shortcuts up with **no game open**, then launch the game. With a game running, Home5 can't write the reader's config (ShadowMountPlus unmounts `/data` from the app). Load `PPSA11019-reader.elf` after the config is in `/data/homebrew/PPSA11019/`.
