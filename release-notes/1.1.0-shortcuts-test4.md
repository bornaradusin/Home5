### Test version 4 — for trying on hardware

A **pre-release** for testing (the updater and ProsperoStore leave it alone). Download `PPSA11019-test.zip` and `PPSA11019-reader.elf` by hand. Reports on the [Shortcuts issue](https://github.com/bornaradusin/Home5/issues/3).

### Since test 3

- **Saving with a game open now reaches the reader.** The app writes the config straight to `/system_tmp` even when a game has `/data` unmounted (test 3 bailed out when it couldn't touch `/data` first). The reader reads its shortcut list from that same `/system_tmp` file, so an edit made mid-game takes effect without a restart — and `FIRE <n>` can't run the wrong shortcut.
- **Rumble pattern.** A third row on the Shortcuts screen, "Rumble pulses" (1–3), for one, two or three short buzzes — a double or triple stands out from a game's own rumble.
- **Steadier reader.** It refuses to start a second time (no more double Home Assistant calls), notices when SceShellUI restarts or exits and stops instead of following a dead thread, and no longer gives up after two hours.
- **Can be autoloaded at boot.** The reader now waits for SceShellUI to come up rather than exiting, so it can go in a payload autoloader and be there from boot without loading it by hand each time (see below).

### About the light bar

Confirmed from test 3: the light-bar call succeeds (`lightbar rc=0x0`), but whatever is in front overrides the colour, so it only shows on the home screen, not over a game or Home5. That's a system limitation, not something Home5 can change. Rumble is the opposite — felt over a game, not on the home screen.

### Starting the reader at boot (optional)

`PPSA11019-reader.elf` can go in a payload autoloader (for example Payload Manager's autoload folder); it now waits for SceShellUI and keeps running, so your shortcuts are there from boot without loading it each time. A one-tap toggle for this inside Home5 is planned once the autoloader path is confirmed.

### Set-up order

You can now change shortcuts with a game open. If an edit still doesn't take (a broken `/data` handoff), close and reopen Home5. Load `PPSA11019-reader.elf` after the config is in place.
