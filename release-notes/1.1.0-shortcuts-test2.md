### Test version 2 — for trying on hardware

A **pre-release** for testing (the updater and ProsperoStore leave it alone). Download `PPSA11019-test.zip` and `PPSA11019-reader.elf` by hand. Reports on the [Shortcuts issue](https://github.com/bornaradusin/Home5/issues/3).

### Fixed since test 1

- **Shortcuts now fire.** The injected thread couldn't read its config: `SceShellUI` can't read `/data`. The loader now copies the config to `/system_tmp`, where the thread reads it. (Thanks EnriqueWood for finding this.)
- The reader's working files are renamed (`/system_tmp/home5_reader.*`), so an older reader's thread can't be mistaken for this one.
- The app now **warns on the Shortcuts screen** when it can't save for the reader — which happens when a game has unmounted `/data`.

### New

- **Trigger an automation** — automations are now in the "What it does" list, run with `automation.trigger`. They also show on the home screen as cards you can trigger.
- **Rumble** as a confirmation — a couple of short vibrations, felt without looking at the screen. Each shortcut's confirmation is now **Light bar / Notification / Rumble / All**.

### Set-up order matters

Set your shortcuts up with **no game open**, then launch the game. With a game running, Home5 can't write the reader's config (ShadowMountPlus unmounts `/data` from the app). Load `PPSA11019-reader.elf` after the config is in `/data/homebrew/PPSA11019/`.

### Still to confirm

The Home Assistant call, the notification, the light-bar flash and the rumble haven't been confirmed on hardware yet — the shortcut never fired in test 1. The first-launch `0x80940033` is ShadowMountPlus's, not Home5's.
